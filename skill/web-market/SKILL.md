# web-market — 단일 파일 브랜드 쇼핑몰

레퍼런스 3종(가상 브랜드, 전부 라이브로 검증):

| 브랜드 | 품목 | 스타일 | 심장 기능 |
|---|---|---|---|
| 결 GYEOL | 수제 도자기 | 에디토리얼 | 한정 수량·"다음 가마 대기" 품절·한 장 사진 다른 프레이밍 썸네일 |
| KEYFORGE | 커스텀 키보드 | 다크모드(오렌지 1색) | 직접 누르는 키보드 인트로·히어로, 스위치별 타건음 듣기 |
| SOOM 숨 | 비건 스킨케어 | 미니멀리즘 | 피부·시간대 루틴 찾기, 3종 세트 10% 할인, 정기배송 −15% |

스타터 = `assets/starter/`(결 GYEOL 전체 코드 + 사진 8장). 복사해서 브랜드만 바꾸면 5화면이 바로 동작한다.

## 1. 코드 전에 네 가지를 정한다

1. **브랜드 한 줄**: 누가, 무엇을, 어떤 약속으로 파는가 ("이천 작업실에서 한 사람이 빚는 생활 도자기").
2. **스타일 하나**: 품목에 맞춰 고른다(예쁜 것 말고). 둘 이상 섞지 않는다. → `references/archetypes.md` 표.
3. **심장 기능 하나**: 이 품목을 살 때만 필요한 기능. 공통 기능(장바구니·옵션)은 기본이고, 여기서 사이트가 갈린다.
4. **첫 화면 장면**: 품목을 직접 만지는 인트로가 어울리면 `signature-hero` 스킬, 차분한 분위기면 `breathing-light`, 둘 다 아니면 큰 사진 히어로.

유저에게 네 가지를 짧게 알리고 진행한다(되돌리기 쉬운 결정이라 허락을 기다리지 않는다).
같은 세션에 여러 몰을 만들면 **스타일·심장 기능·첫 화면이 서로 겹치지 않게** 한다. 한 스켈레톤을 색만 바꿔 찍어내면 반려된다.

## 2. 구조 (스타터 그대로)

```
<폴더>/
├── index.html      전부 여기 — CSS·마크업·JS
├── img/            hero · 상품 6 · 이야기 1 (파일명 = 데이터의 img 값)
├── .gitignore      img/raw/ .DS_Store .vercel
└── .vercelignore   img/raw  img/PROMPTS.md  .env*
```

- **데이터는 한 곳**: `P` 배열(상품), `CATS`(분류), `FREE`·`SHIP`(배송비). 상품 필드: `id name en cat price img tag rank desc opts spec soldout`.
- **옵션 가격**은 라벨에 적는다: `'24cm (+60,000)'` → `optDelta()`가 파싱해 합산. 별도 가격표를 만들지 않는다.
- **라우팅**: `#/` 홈 · `#/shop?c=&s=` 목록(분류·정렬) · `#/p/<id>` 상세 · `#/checkout` 주문서 · `#/done` 완료. `#/#story`는 홈의 섹션 링크.
- **장바구니**: 키 = id + 옵션 JSON, 수량 1~9, `localStorage`는 try/catch로 감싼다(사생활 모드에서도 동작).
- **결제는 데모**: 주문서 상단에 "예시 사이트 — 실제 결제는 이뤄지지 않습니다", 완료 화면에도 한 번 더.

## 3. 쇼핑몰이라면 반드시 있는 것

- 무료배송까지 남은 금액 + 진행바(드로어 상단)
- 카드: 사진 4:5, 이름·영문/부제·가격, 태그(베스트·신작·한정), 품절 표시, 호버 "바로 담기"(터치 기기에선 숨김)
- 상세: 썸네일 갤러리 + 클릭 확대·팬, 옵션 칩(radiogroup), 수량, 담기 → 드로어 자동 열림, 스펙 `dl`, 배송·교환·반품 아코디언, 함께 사면 좋은 상품
- 품절: 버튼 비활성 + 재입고 시점("10월 셋째 주 가마")
- 주문서: `autocomplete`·`inputmode`·`pattern`, `:user-invalid`일 때만 오류 문구, 첫 오류로 포커스, 결제 동의 체크, 결제 버튼에 최종 금액
- 완료: 이름·주문번호·금액·결제수단 (sessionStorage)
- 접근성: 토스트 `aria-live`, Escape로 드로어·메뉴 닫기, 드로어 열리면 body 스크롤 잠금, `:focus-visible`
- 푸터: 상호·대표·주소·사업자번호·통신판매업 번호 자리 — 가상이면 "(가상)"과 "포트폴리오 예시 사이트" 표기
- `prefers-reduced-motion`에서 모든 모션 끔

## 4. 디자인 기준

- 배경은 순백·순검정 금지(라이트 #F2~#F7, 다크 #08~#1F). 강조색 1개.
- 본문 14~15px, radius는 한 계열만(타이트 2~8 / 소프트 14~32 / pill).
- transition 160ms ease-out, 큰 모션 480ms `cubic-bezier(.16,1,.3,1)`.
- 영문 모노 대문자 라벨·섹션 번호(01/Nº)·가는 선 표 금지 → 한글 작은 글씨, 카드. 한글 제목 700~800·자간 −0.01~−0.02em (에디토리얼 세리프는 300~400 허용).
- 버튼 수식 클래스 이름을 다른 컴포넌트 이름과 겹치지 않게(`.btn.line` ↔ `.line` 충돌로 레이아웃이 깨진 적 있음). `.btn.dark` `.btn.ghost`처럼 고유하게.

## 5. 사진

상품 6 + 히어로 1 + 이야기 1 = 8장. 같은 조명·배경 문구를 모든 프롬프트 끝에 붙여 톤을 맞춘다. 생성·저장·워터마크 처리는 `references/production.md`.
사진이 없을 때도 화면이 무너지지 않게 `.ph`에 배경색을 둔다.

## 6. 검증 — 안 봤으면 완료라고 하지 않는다

```bash
cd <폴더>/.. && python3 -m http.server 8765 &        # 한글 폴더명도 됨
node <스킬>/scripts/verify.mjs http://127.0.0.1:8765/<폴더>/ <출력폴더> <상품id>
```
폭 320·390·430·1440에서 홈·목록·상세·드로어·주문서·완료 스크린샷을 직접 열어 본다. `CHECK`·가로넘침·콘솔 오류가 0이어야 한다.
중간 폭(700~900)도 한 번 본다 — 그리드가 2열로 바뀌는 구간에서 카드 메타가 깨지기 쉽다.

첫날 private 레포에 push하고 Vercel 정적 배포. 명령과 도메인 선점 대처는 `references/production.md`.
